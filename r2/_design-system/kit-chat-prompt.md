# Стартовый промпт для чата по дизайн-системе

Скопировать в новый чат Claude Code, запущенный из `~/Documents/roman-docs`.

---

Работаем над **дизайн-системой прототипов**: `01-cian/Projects/_design-system/`.
Компоненты, токены, типографика, киты, сверка с прод-китом ЦИАН, поверхность iOS.
Продуктовые решения по отчёту о цене и конкурентах — в другом чате, сюда не тащим.

**Прочитай перед первым действием, а не пересказывай по памяти:**
`01-cian/Projects/CLAUDE.md` (контекст и токены) → `_design-system/design-system.md`
(устройство) → `surface-app.md` (поверхность iOS, там же раздел про киты) →
`prod-parity.md` (что сверено с прод-китом, что нет, как туда ходить).

**Термины.** «Кит» — наши страницы `kit.html` и `kit-app.html`, связаны переключателем.
«Витрина» — эталон ЦИАН: storybook `@cian/ui-kit` для веба, TestFlight-сборка для iOS.
Одним словом оба не называть.

**Посмотреть киты:**

```bash
cd 01-cian/Projects && python3 -m http.server 8000
# http://localhost:8000/_design-system/kit.html      и  /kit-app.html
```

Тесты прототипа (нужны, если правка задела компоненты):
`report-price-and-competitors/v-next/tests/run.sh`.

**Как здесь принято работать:**

- Вердикт даёт рендер, а не свойства узлов и не зелёные тесты. Мерить в браузере.
- Отступы кратны 4; цвета только токенами. Нет подходящего токена — это дырка в ДС,
  сказать вслух, а не красить руками.
- Правки вёрстки, коммиты и деплой — по явной команде. Изменения писать в CHANGELOG.
- Кратко, по-русски, без поддакивания. Костыли не предлагать.
- Сабагентов, workflow и deep-research не звать без просьбы. Figma по MCP — свободно.

Начни с короткого доклада: что нашёл в ДС, какие расхождения с прод-китом открыты,
что сам считаешь первыми двумя-тремя шагами.
