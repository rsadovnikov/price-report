# Прототип — как заводится, из чего собирается, чем проверяется

Стек — **vanilla HTML + CSS + JS, без сборки**: страницы раздаются статическим сервером с
корня `01-cian/Projects/` и открываются браузером. Это осознанный выбор, а не долг.

- **Образец:** `report-price-and-competitors/v-next/` — девять экранов на двух поверхностях,
  48 смоук-тестов, деплой на GitHub Pages. Его `CHANGELOG.md` — за что куплены решения.
- **Заготовка:** [`template/`](template/) — копируется целиком и работает: две страницы,
  подключение к базе, раздача, тест, сборка. Состав — в [`template/README.md`](template/README.md).

Документ ведётся как единственный источник порядка сборки. Шаги здесь, а не в README
шаблона и не в `CLAUDE.md` прототипов: два описания одного порядка разойдутся молча.

## 1. Папка

```bash
cd 01-cian/Projects
cp -r _design-system/template <проект>/<папка>     # например report-price-and-competitors/v-next
```

**Глубина — ровно два уровня от `Projects/`.** Страницы подключают ДС как
`../../_design-system/`, а `serve.sh`, `tests/run.sh` и `tests/config.js` считают путь к
прототипу от своего положения. Положить папку глубже или выше — и пути не соберутся.

Что лежит в папке прототипа:

| файл | роль |
|---|---|
| `*.html` | экран: только разметка и подключения. Стили — в своём `.css`, логика — в своём `.js` |
| `*-app.html` + `*-app.js` | экраны **приложения**. Суффикс — контракт: сборка образца кладёт их глобом в `/app/` |
| без суффикса | вебовые страницы и модули, общие для двух поверхностей (`filters.js`, `preset.js` в образце) |
| `mock-scenario.js`, `mock-connect.js` | подключение базы — п. 4 |
| `dev-reset.js` | ⌘⇧R — сброс `sessionStorage` и возврат на первый экран; инструмент показа, не ДС |
| `serve.sh`, `tests/`, `deploy-pages.sh` | инфраструктура из шаблона; править только строки «настройка проекта» |
| `CLAUDE.md`, `CHANGELOG.md` | инструкция подпроекта и лог решений — п. 9 |

**Скрипты — классический `<script src>`, не `type="module"`:** инлайн-хендлерам
(`data-action`, `onerror`) нужны глобальные функции, модуль их спрячет. Единственное
законное исключение из «html = разметка» — однострочный FOUC-guard в `<head>`, которому
надо отработать до первой отрисовки (образец: `report.html`, класс `activating`).

Имя файла — контракт сборки. В образце `preset-app.js` носил суффикс приложения, читался
обеими поверхностями и уезжал сборкой не туда (2026-08-23); переименован в `preset.js`.

## 2. Анализ до кода

Коротко ответить, потом писать:

- **Задача:** что пользователь делает на экране, какое действие главное.
- **Ключевой момент:** одно состояние или переход, ради которого экран существует.
- **Компоненты:** что из кита подходит как есть; что придётся заводить (п. 5).
- **Состояния:** пусто, заполнено, выключено, ошибка, загрузка.
- **Данные:** что берётся из базы, что задаёт сценарий, что живёт у экрана (статистика кабинета).

## 3. Поверхности и порядок подключения

Порядок: **шрифт → токены → поверхность → база → надстройка → компоненты → страница.**
Файл поверхности переопределяет только `--type-*`; всё остальное общее.
Полный список компонентов — `kit.html` и `kit-app.html`, подключать только нужные.

### Веб (десктоп)

```html
<link rel="stylesheet" href="../../_design-system/fonts.css">      <!-- Lato файлом: у Google Fonts нет кириллицы -->
<link rel="stylesheet" href="../../_design-system/tokens.css">
<link rel="stylesheet" href="../../_design-system/base.css">
<link rel="stylesheet" href="../../_design-system/web.css">        <!-- шапка, лейаут, сайдбар -->
<link rel="stylesheet" href="../../_design-system/components/buttons.css">
<link rel="stylesheet" href="web.css">                              <!-- страница — последней -->
…
<div id="header"></div>
<div class="layout"><div id="sidebar"></div><main class="main-content">…</main></div>
<script src="../../_design-system/components/header.js"></script>
<script src="../../_design-system/components/sidebar.js"></script>
<script>renderHeader('../../_design-system/'); renderSidebar({ active: 'Мои объявления' });</script>
```

Веб — только десктоп (решение 2026-08-15). Телефон обслуживает поверхность приложения.

### Приложение (iOS)

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<meta name="format-detection" content="telephone=no, date=no, address=no, email=no">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="mobile-web-app-capable" content="yes">
<link rel="stylesheet" href="../../_design-system/tokens.css">
<link rel="stylesheet" href="../../_design-system/tokens/surface-app.css">   <!-- SF Pro и своя шкала -->
<link rel="stylesheet" href="../../_design-system/base.css">
<link rel="stylesheet" href="../../_design-system/components/app/screen.css">
<link rel="stylesheet" href="../../_design-system/components/app/navbar.css">
<link rel="stylesheet" href="../../_design-system/components/app/page-transition.css">
<script src="../../_design-system/components/app/page-transition.js"></script>  <!-- в <head>, без defer -->
<link rel="stylesheet" href="app.css">
```

- `web.css` и `fonts.css` не подключать: шапки и сайдбара нет, SF Pro системная.
- `format-detection` — на каждом экране: Сафари превращает цены в телефонные ссылки, и в
  Chromium это не воспроизводится, поэтому тест в образце проверяет тег статически.
- Экран — `<div class="screen-app">` из белых `.card-app` на сером фоне; ширина 360…412
  задана в одном месте (`components/app/screen.css`). Мок статус-бара прячется там, где есть настоящий.
- Переход между экранами делает браузер (cross-document View Transitions); скрипт
  направления обязан стоять в `<head>` без `defer`.
- Роли типографики те же, значения другие; вес Semibold — 600, не 590. Подробно — [`typography.md`](typography.md).

Как поверхность устроена и что уже снято — [`surface-app.md`](surface-app.md).

## 4. Данные

Общая база настоящих объявлений в модели ЦИАНа — `../_mock-data/`. Подключается четырьмя
строками, в этом порядке:

```html
<script src="../../_mock-data/mock.js"></script>                           <!-- клиент -->
<script src="../../_mock-data/datasets/cian-secondary/listings.js"></script> <!-- датасет -->
<script src="mock-scenario.js"></script>   <!-- чьи объявления и что показать снятым -->
<script src="mock-connect.js"></script>    <!-- Mock.use() и пересчёты прототипа -->
```

| где | что там живёт | чего там не бывает |
|---|---|---|
| датасет | просто объявления, зеркало страниц ЦИАНа; собирается набегом, руками не правится | ролей «моё / чужое», флагов сценария |
| `mock-scenario.js` | `base` — id объявлений агента по порядку показа; `archived` — показать снятыми | данных |
| `mock-connect.js` | `Mock.use()`, свои имена полей, пересчёты, разбор строк прода в числа | того, что нужно другому прототипу |
| экран | то, чего нет в публичной выдаче: звонки, ставка, позиция | фактов объявления |

API клиента: `Mock.base(i)`, `Mock.bases()`, `Mock.listings({ rooms, areaFrom, areaTo, priceFrom, priceTo, removed })`,
`Mock.meta()`. Записи копировать, а не править на месте — кеш общий. Пропуски не выдумывать:
источник не отдал поле — пусто и прочерк. Пересобирать набор — только в новый датасет.
Как ведётся набор — `../_mock-data/README.md` и скилл `mock-dataset`.

## 5. Компоненты: что своё, что в ДС

- **Токены — только переменными.** Справочник в `../CLAUDE.md`, полный файл `tokens.css`.
  Нет подходящего токена — это дырка в ДС: сказать вслух, а не красить руками.
- **Типографика — только ролями** (`.heading1`…`.overline` или `--type-*`). `font-size: 14px`
  в компоненте не пойдёт за сменой поверхности.
- **Кнопки:** веб — `btn-{primary|secondary|outline|ghost}-{lg|md|sm}`; приложение — `.btn-app`
  с осями `--primary|--secondary` × `--main|…` × `--small|--medium|--large`. Классы по контексту
  (`.btn-report`) не заводить.
- **JS-хуки — `id` или `data-action`**, CSS-классы только для вида.
- **Порог выноса в ДС — второе применение.** Одно применение живёт у экрана, с записью в
  `CHANGELOG.md`. Компонент в ДС — это файл в `components/` или `components/app/`, экспонат в
  ките и запись в `surface-app.md` (приложение) или `prod-parity.md` (веб).
- **ДС не править походя:** она общая и стоит под тестами образца. Чинить в компоненте, а не
  у потребителя; не оставлять API «про запас» — неиспользуемое читается как рабочий сценарий.
- **Правило — в одном месте.** Два экрана, считающие одно и то же, обязаны читать один модуль
  (образец: `updates-app.js`, `filters.js`), иначе разойдутся молча.
- **Иконки** — экспорт из Figma в `assets/icons/`, цвет запечён. Глифу, который должен взять
  цвет текста, — инлайновый `<svg fill="currentColor">`.
- **Анимации** — только со смыслом (появление, исчезновение, отклик), 150–200 мс,
  `prefers-reduced-motion` гасит.

## 6. Запуск

```bash
./serve.sh              # сервер с корня Projects/, адреса всех страниц, QR на страницу по умолчанию
./serve.sh report       # QR на report.html (.html можно не писать)
./serve.sh kit          # QR на витрину приложения
```

Телефон и мак — в одной Wi-Fi, наружу ничего не уходит. Сервер отдаёт `no-store`: обычный
`python3 -m http.server` даёт браузеру кешировать CSS, и правку «не видно». На айфоне
открывать через «Поделиться → На экран „Домой“» — тогда мок статус-бара уступает настоящему.
Прототип показывать на телефоне, а не только узким окном: платформа дорисовывает то, чего в
разметке нет (телефонные ссылки из цен нашлись только так).

## 7. Тесты

```bash
./tests/run.sh                 # весь набор; сам поднимает сервер и гасит его
./tests/run.sh smoke-pages     # один тест
```

- Окружение — только из `tests/config.js`: `ORIGIN` считается из положения папки, `KIT` /
  `KIT_APP` — киты, `SMOKE_ORIGIN` перебивает (прогнать сборку на `:8010`).
- Один `smoke-*.js` на экран минимум. Образец — `template/tests/smoke-pages.js`; полный набор
  правил — `../report-price-and-competitors/v-next/tests/README.md`.
- **Ожидание считать из данных, не вписывать числом. Два места одной правды сверять между
  собой. Проверять рендер, а не свойства узлов. Список экранов — из содержимого папки.**
- Прогон — до и после каждой правки. Тест покраснел — разобраться, изменилась база или
  сломано поведение; не подгонять ожидание под результат.
- Прогон идёт с `reducedMotion: 'reduce'` — переходы между экранами под Playwright-Chromium
  вешают страницу. Зелёный прогон не доказывает, что переход играет: смотреть живым Chrome.

## 8. Деплой

```bash
./deploy-pages.sh                      # dry-run: сборка в dist-pages/, проверки
./deploy-pages.sh --push "сообщение"   # пуш — ТОЛЬКО по явной команде Романа
```

Настройка — три строки вверху скрипта: `PROD_REPO` (без него `--push` отказывает), `PREFIX`
(каталог на сайте; старые ссылки после смены префикса ведут на заглушку), `ASSET_DIRS`.

Что делает сборка: копирует ДС без китов и шаблона, из `_mock-data` — только клиент и
датасет (там свой `.git`, целиком копировать нельзя), переписывает `../../` в пути рядом,
штампует CSS/JS версией (Pages кеширует статику 10 минут), кладёт `.nojekyll` (иначе Pages
прячет `_design-system/`), проверяет, что ни одно подключение не ведёт в пустоту.
Образец с двумя корнями (`/PREFIX/` веб, `/PREFIX/app/` приложение) —
`../report-price-and-competitors/v-next/deploy-pages.sh`.

Репозиторий Pages публичный: в него уходит только публичная выдача классифайдов. Историю
проверять **до** смены видимости — она раскрывается целиком.

## 9. Документы прототипа

- `CLAUDE.md` — заготовка в шаблоне: правила (design-lock, маршрутизация, лог), файлы, деплой.
- `CHANGELOG.md` — каждое изменение: что, почему, чем проверено. Ошибки рассуждения — тоже,
  они и есть самое ценное для следующего.
- Комментарий в коде — только с проверенным происхождением. «Снято с прода» без замера
  закрывает вопрос, который остаётся открытым, — это хуже отсутствующего комментария.
- Персональные данные в документах — имя и первая буква фамилии.
