# Типографика прототипа — Magentum Desktop/Typography

Шрифт: **Lato** (все токены).

> ⚠️ **Lato с Google Fonts НЕ содержит кириллицу** (только latin/latin-ext) — кириллический текст падает в системный шрифт, а латиница/цифры остаются в Lato (визуальный рассинхрон). В прототипах подключать Lato из источника с кириллицей, напр. `https://fonts.cdnfonts.com/css/lato`, а не `fonts.googleapis.com`.

## Правила применения

1. Все текстовые стили в прототипе должны использовать только токены из этой таблицы.
2. Инлайновые стили `font-size` / `line-height` / `font-weight` допустимы только если нет подходящего токена.
3. При добавлении нового текстового элемента — выбирать ближайший подходящий токен, а не произвольные значения.
4. `letter-spacing` обязателен для Heading1–6 и Overline; для остальных равен 0.
5. `text-transform: uppercase` применяется только к `.overline`.
6. Для всех текстовых стилей: `font-feature-settings: 'liga' off, 'clig' off` (лигатуры выключены, как в Figma-спеке) и `font-family: var(--font-base, 'Lato', sans-serif)` с фолбэком.

## Поверхности: веб и приложение

Роли одни и те же, значения разные. Шкала выше — **вебовая**; приложение переопределяет
её целиком в `tokens/surface-app.css` (снято с Figma «🍏 iOS» → Fonts, 2026-08-14).

| роль | веб (Lato) | iOS (SF Pro) |
|---|---|---|
| Heading1 | 28 / 36 / −0.5 / 700 | 36 / 43 / +0.36 / 600 |
| Heading2 | 22 / 28 / −0.5 / 700 | 28 / 34 / +0.36 / 600 |
| Heading3 | 18 / 24 / −0.5 / 700 | 22 / 27 / +0.35 / 600 |
| Heading4 | 16 / 24 / −0.2 / 700 | 16 / 20 / −0.32 / 600 |
| Heading5 | 14 / 20 / −0.2 / 700 | 14 / 17 / −0.24 / 600 |
| Heading6 | 12 / 16 / −0.2 / 700 | роли нет, достроена как 12 / 15 / 0 / 600 |
| Body1 | 16 / 24 / 0 / 400 | 16 / 20 / −0.32 / 400 |
| Body2 | 14 / 20 / 0 / 400 | 14 / 17 / −0.24 / 400 |
| Caption | 12 / 16 / 0 / 400 | 12 / 15 / 0 / 400 |
| Overline | 10 / 16 / +1 / 700 | 10 / 12 / +0.3 / 400 |

*кегль / интерлиньяж / трекинг / вес*

Что из этого важно помнить:

- **Заголовки в приложении на ступень крупнее** (H1 36 против 28, H2 28 против 22,
  H3 22 против 18), а H4 и H5 совпадают по кеглю. Перенести вебовый экран «как есть»
  нельзя — верхние заголовки вырастут, нижние нет, иерархия перестроится.
- **Текст плотнее:** интерлиньяж к кеглю ≈1.2 против ≈1.45 в вебе. Тот же абзац займёт
  заметно меньше высоты.
- **Значения переносятся числами, а не коэффициентом.** Трекинг у крупных заголовков
  даже меняет знак: +0.36 в приложении против −0.5 в вебе.
- **Вес 600 (Semibold), не 700.** У SF девять весов — Ultralight 100 … Black 900, —
  и системный стек их достаёт: замер даёт 10 разных ширин на 10 значений, рендерит
  `.SF NS`. Так что «только regular и bold» — не про этот шрифт.
  > ⚠️ **Но не 590.** Figma в коде отдаёт `font-[590]` — это значение оси `wght`
  > вариативного файла SF Pro (Apple ставит Semibold на 590, а не на 600), а не вес CSS.
  > Скопированное в `font-weight`, оно рисуется **тяжелее** настоящего Semibold: по
  > сумме альфы на 28px 590 даёт 970 против 923 у 600 и 935 у 610 — почти как 650,
  > при том что строка уже. Кривая монотонна везде, кроме этой точки. До 2026-08-15
  > у нас стояло 590, и из-за этого все заголовки на поверхности приложения выглядели
  > жирными. Та же ловушка «число вместо роли», только на уровне шрифта.

### Как подключать

```html
<link rel="stylesheet" href="../../_design-system/tokens.css">
<link rel="stylesheet" href="../../_design-system/tokens/surface-app.css">  <!-- только в app-прототипах -->
<link rel="stylesheet" href="../../_design-system/base.css">               <!-- применение ролей к классам -->
```

Палитра, отступы и радиусы общие — поверхность их не трогает. Применение ролей к
классам живёт в `base.css` и от поверхности тоже не зависит: правила читают
переменные, а какие в них значения — решает файл поверхности.

### Правило

Значения ролей живут **только** в токенах `--type-*`. В компоненте писать `font-size: 14px`
нельзя: такой размер не пойдёт за сменой поверхности, и в приложении там останется
вебовое число.

Исключение — **кастомные текстовые стили**, которых нет в шкале. Сейчас их пять:
`.gallery__counter` (13/16), `.input-m .input__control`, `.segmented-item`, `.tab`,
`.tab .tab-counter` (16/22). Они помечены комментарием в коде. Если приложению нужны
свои значения — заводить app-дельту компонента, а не подгонять роль.
